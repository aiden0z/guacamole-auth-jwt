# 1.6.0 多会话与共享设计

状态：用户已确认；功能已实现并完成本地验证，待托管 CI 与发布验收。2026-09-06。

## 目标和发布边界

1.6.0 的发布要求包括 #6、#12 及 example app 对应流程。现有第一批兼容性、安全、打包和单连接验证继续保留，但不能作为这两项的验收证据。设计按同时覆盖官方 Guacamole Web UI 和内嵌 example client 推进。

保持旧版平铺 JWT、`GUAC_ID`、header/form 两种传递方式及 Java 8 字节码兼容。目标宿主为 Guacamole Web/guacd 1.6.0。不以本次工作承诺其他宿主版本或生产部署已验证。

## 证据与方案选择

- [#6](https://github.com/aiden0z/guacamole-auth-jwt/issues/6) 描述的是官方界面在同一浏览器中分别登录第二个连接后，第一个连接断开；原作者的简单客户端没有该问题。
- Guacamole 1.6.0 的 [authenticationService](https://github.com/apache/guacamole-client/blob/1.6.0/guacamole/src/main/frontend/src/app/auth/service/authenticationService.js) 从共享的 `GUAC_AUTH_TOKEN` 存储取得旧 token，在新登录返回不同 token 时撤销旧 token。仅改变连接 ID 无法修复这一行为。
- 官方扩展格式支持在 manifest 中声明随界面加载的 JavaScript，但对内部 Angular 服务的适配仍需版本回归，不能视为稳定的跨版本接口。
- [官方 JSON 认证](https://guacamole.apache.org/doc/1.6.0/gug/json-auth.html) 的 `id`/`join` 和 [ConnectionService](https://github.com/apache/guacamole-client/blob/1.6.0/extensions/guacamole-auth-json/src/main/java/org/apache/guacamole/auth/json/connection/ConnectionService.java) 展示了通过 guacd 活动连接 ID 加入现有连接及关闭访客 tunnel 的机制。

选择：插件附带、显式启用的标签页隔离，加服务端活动连接共享。仅支持内嵌客户端不足以覆盖 #6；仅增加一个 JWT 内的多连接列表也不能覆盖分别登录的原始场景。Fork 官方 Web UI 会扩大维护范围，本版不采用。

## #6：独立标签页登录

- 官方界面入口增加 `jwt-tab=1` 标记，启用该标签页的隔离模式；example app 的“在官方界面打开”入口负责附加标记。
- 插件 JavaScript 通过 manifest 加载，用 Angular 装饰器适配认证存储。只在隔离模式下将 `GUAC_AUTH_TOKEN` 路由到独立命名的 sessionStorage 槽位；其他用户偏好仍沿用原存储服务。不全局替换浏览器 Storage API，不修改 upstream WAR，不用 Nginx 字符串注入。
- 启用状态在当前标签页刷新后保留；不从共享 localStorage 迁移 token。sessionStorage 不可用时退回当前页面内存，刷新后重新登录，不能回退到跨标签页共享认证。
- 每次通过门户独立打开的窗口使用 `noopener`，分别授权，不通过 opener 复制 sessionStorage。浏览器“复制标签页”可能复制同一个会话；不把浏览器复制动作宣称为一次独立登录。
- A、B 分别登录时不得撤销彼此 token；同一标签页主动换用户或退出仍撤销该标签页原 token。普通未启用隔离的官方登录行为保持原样。
- 隔离模式适用于整个标签页的认证流程，包括同一页内后续切换认证源；文档说明它不再提供该标签页与其他标签页之间的自动登录共享。
- 内嵌 Console 使用自己的每标签页状态，新增独立打开入口；普通官方会话刷新使用有效 token 恢复；共享宿主刷新结束当前一代会话，必须重新授权并取得新的共享 ID。这一收敛避免旧邀请加入重连后的会话。签名密钥和远程密码始终仅在后端。

## #12：加入活动连接

保留普通连接 JWT，新增两个可选、互斥的顶层字符串声明：

- `GUAC_SHARE_ID`：普通连接可被共享的标识。由受信任签发端为每次宿主连接生成至少 128 位随机值。不能直接用可预测的桌面名或把同一个 `GUAC_ID` 当成共享许可。
- `GUAC_JOIN_ID`：访客被授权加入的共享标识。加入 JWT 仍必须有有效签名、`exp` 和合法 `GUAC_ID`，但不得携带目标主机、密码或协议参数；只允许 `guac.read-only`，取值为 `true`/`false`，缺省为只读。未知连接参数拒绝，避免访客覆盖宿主目标或扩大授权。

声明名称是本扩展的新接口，须在实现时固定并在 README 给出完整宿主/访客示例。普通旧 JWT 不包含这些声明时保持现有行为。

服务端增加一个 provider 实例级活动连接注册表，将共享标识映射到握手成功后得到的 guacd connection ID。加入操作只接受注册表中的活动条目，绝不接受客户端直接指定的原始 guacd ID。

同一共享标识的并发宿主连接拒绝后来的请求，不能静默替换原连接。注册、加入和关闭必须处理竞争：宿主关闭后不得留下可加入条目或孤立访客；连接建立失败必须释放预约；重复关闭安全。宿主结束时关闭其访客 tunnel。重新连接宿主时签发新的共享标识，旧链接不能加入新一代会话。

`exp` 在认证和建立共享 tunnel 时均检查，防止先兑换 token 再延后加入。它限制加入时间，不表示到期即强制断开已经加入的访客。宿主关闭终止所有访客。逐访客撤销、到期主动踢出和跨实例共享不纳入本版；这三项不能在 UI 中暗示为已有能力。

权限在服务端和 guacd 层落实；前端禁用键盘只能改善体验，不能作为只读保护。只读验收同时检查键鼠、剪贴板和文件通道；任何不能可靠禁止的写入通道必须关闭后才能宣称只读支持。

服务端状态保存在内存，重启后共享失效。多实例必须保持宿主和访客落到同一 Guacamole 实例及对应 guacd；本版只验证单实例，不增加数据库或 Redis。

## Example app

- 连接页提供内嵌 Console 和官方 Web UI 两个入口，能分别打开两个独立会话。
- 后端为每次普通连接生成随机共享标识并保存其所属 demo 授权会话。浏览器不能通过提交任意共享标识创建邀请。
- 内嵌 Console 提供“生成共享链接”：默认只读，可显式选择允许控制。后端确认宿主归属后保存短期随机邀请 capability；示例邀请期限为 5 分钟。
- 访客页从 URL fragment 读取邀请 capability，随 POST 发给 broker，broker 验证邀请后签发短期加入 JWT 并在服务端兑换 Guacamole token。邀请链接不包含签名密钥、JWT 或桌面密码；打开后移除 fragment，响应禁止缓存。链接持有者拥有相应访客权限，UI 明确提示。
- 不通过任意 URL 主机头拼接外部地址。日志不得包含邀请 capability、JWT、Guacamole token、签名密钥或远程密码。
- 提供宿主未连接、已断开、邀请过期和权限错误的明确反馈。共享建立是否有效最终由插件检查活动连接，不能仅凭 broker 记录判断。
- 官方界面用于验证独立登录和访客连接；本版的邀请生成入口放在 example app，不承诺新增官方 JDBC 风格的 Sharing Profiles 管理界面。

## 文件与组件边界

- `AuthenticationProviderService.java`：签名校验和新声明的严格解析，避免日志泄漏。
- `JwtAuthenticationProvider.java` 及新增 user context/connection 类：将解析后的授权转换成普通或共享连接，保留旧认证行为。
- 新增活动连接注册表与 tunnel 生命周期类：并发预约、登记、加入、清理和宿主关闭传播。
- `src/main/resources/guac-manifest.json` 及新增 JavaScript：官方界面的可选标签页认证存储适配。
- `example-app/backend/`：宿主归属、邀请 capability、加入 token 的服务端兑换。
- `example-app/frontend/src/`：双入口、多标签页和共享访客流程。
- `scripts/`、Java/backend tests 和 CI：协议、授权、并发和真实浏览器回归。

若参考实现需要复制 Apache 源代码，保留相应许可证和来源说明；不将 auth-json 扩展 JAR 整体装入本扩展来调用其内部服务。

## 最强反方与失败条件

最强反方是前端隔离依赖 Guacamole 内部实现，服务端共享也引入了原先无状态插件没有的生命周期复杂度。若隔离适配影响普通登录、只读限制不能由服务端保证、共享关闭存在竞态泄漏，或只能演示内嵌客户端而无法复现并通过官方界面场景，则 1.6.0 保持未发布，不以改写 issue 范围代替修复。
