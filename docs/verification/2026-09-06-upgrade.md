## Integration environment and limits

- macOS host, Linux ARM64 Docker containers. Official Guacamole Web and guacd 1.6.0 images. The tested Web container reports Temurin 21.0.7; this records the actual runtime and does not assert that its JDK/base-image patches are current.

- guacd image ID: `ad352d5923f392e753d983d951939a699a1b4044ae3108419f03f42afcdf231d`.
- The host's Docker mirror failed, and BuildKit's token fetch timed out. Images were pulled through the explicit official registry; the two local fixture images were built with `DOCKER_BUILDKIT=0 docker build`, then started using Compose `--no-build`. No global Docker configuration was changed. The CI BuildKit path itself has not run on GitHub.
- Deliberate negative authentication cases initially hit upstream's normal 429 ban. `compose.test.yaml` raises the failed-attempt limit only for this test stack, so the individual 403 rejection cases can be asserted. Normal example configuration keeps upstream defaults.
- Remaining build notices: Guacamole's legacy request API is deprecated, and Vite reports a bundle larger than 500 kB. Neither failed the scoped checks. No Java 25 unit matrix, Guacamole 1.6.1, RDP/SSH session, existing JDBC database migration or production deployment was verified.
- GitHub Actions configuration is written; hosted matrix/release execution is pending. Local container integration covers a Java 21 runtime but is not a substitute for the hosted Java 21 unit-test job.
- Multi-session issue #6 and sharing issue #12 were not covered by these first-batch checks. Both are now required for the 1.6.0 release, including their example-app flows; this report is not release acceptance evidence for either issue.

The isolated test stack and browser are stopped after verification. Generated demo secrets remain only in the ignored, private `example-app/.env`; legacy local demo artifacts are retained but excluded from the mounts.

Next step: implement and verify #6 and #12 together with their example-app flows. After those release requirements pass, run the hosted checks and the target deployment's upgrade rehearsal before publishing 1.6.0.
